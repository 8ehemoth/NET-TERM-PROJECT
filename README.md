# 네트워크프로그래밍및실습

강원대학교 네트워크프로그래밍및실습 수업에서 진행한 **Windows GUI 기반 TCP 클라이언트·서버 텀 프로젝트**와 학습 기록을 정리한 저장소입니다.

C++과 Winsock2, Windows API를 활용해 사용자 ID 등록, 다자간 채팅, 최근 대화 복원, 파일 전송, 계산기 및 접속자 관리 기능을 구현했습니다. 메시지 타입과 길이 정보를 정의하고, GUI와 네트워크 처리를 연동하며 소켓 통신과 동기화 과정을 학습했습니다.

최종 프로젝트의 서버·클라이언트 분리 구조와 GUI를 유지하면서 버퍼 범위 검사, 부분 송수신, 송신 대기열 및 입력 검증을 보완했습니다. 아래 설명은 해당 개선본을 기준으로 합니다.

## 주요 기능

| 기능 | 주요 내용 |
| --- | --- |
| 서버 접속 | 서버 IP를 입력해 TCP 연결 수립 |
| 사용자 ID 등록·변경 | 빈 ID·중복 ID 검사 및 서버 승인 처리 |
| 다자간 채팅 | 송신자를 제외한 연결 클라이언트에 메시지 전달, 송신자 화면에는 전송 내용 표시 |
| 최근 대화 복원 | ID 등록 시 서버 메모리에 저장된 최근 20개 이력 전달 |
| 파일 전송 | 클라이언트에서 서버로 파일 업로드, 진행률 및 저장 결과 표시 |
| 계산기 | 별도 TCP 연결로 사칙연산 요청 및 결과 수신 |
| 접속자 관리 | 서버 접속자 목록 표시 및 선택한 사용자 강퇴 |
| 편의 기능 | Enter 입력 처리, 이모티콘 3종 및 디버그 로그 |

파일 전송은 클라이언트→서버 단방향이며, 최대 16 MiB 파일을 서버 작업 폴더의 `received_files/`에 저장합니다. 같은 이름의 파일은 덮어쓰지 않고 오류를 반환합니다. 전송률 100% 이후 서버의 저장 완료 응답까지 확인해야 합니다.

계산기는 음수·소수를 포함한 두 피연산자의 단일 사칙연산을 지원합니다. 괄호나 복합 수식은 지원하지 않으며 잘못된 수식과 0으로 나누기는 오류로 처리합니다.

## 통신 및 처리 구조

| 구분 | 처리 방식 |
| --- | --- |
| ID·채팅·파일 | TCP 9000 연결 사용 |
| 계산 요청 | TCP 9001에 별도 연결 |
| 메시지 구분 | 메시지 타입과 길이 정보를 포함한 헤더 사용 |
| 서버 I/O | `select()` 기반으로 여러 연결의 수신·송신 처리 |
| 수신 처리 | 연결별 버퍼에 데이터를 누적하고 완성된 패킷 단위로 처리 |
| 송신 처리 | 연결별 송신 큐와 오프셋으로 전송 순서 및 부분 송신 관리 |
| GUI 연동 | 수신·파일·계산 작업을 작업 스레드에서 처리하고 UI 갱신 요청 전달 |
| 공유 자원 | 임계영역 등으로 공유 상태 접근 관리 |

TCP는 바이트 스트림이므로 한 번의 `send()`가 한 번의 `recv()`에 대응하지 않습니다. 헤더와 본문이 나뉘거나 여러 메시지가 합쳐져 도착하는 상황을 고려해 길이 기반으로 메시지 경계를 판별합니다.

기존 Windows 프로젝트의 구조체와 little-endian 형식을 사용합니다. 다른 플랫폼이나 언어와 연동하려면 바이트 순서와 직렬화 규약을 별도로 정의해야 합니다.

## 저장소 구성

| 경로 | 주요 역할 |
| --- | --- |
| `Term_Server/` | 서버 GUI, 연결 관리, 채팅 중계, 대화 이력, 파일 저장, 계산 및 강퇴 처리 |
| `Term_Client/` | 클라이언트 GUI, 서버 접속, ID·채팅 송수신, 파일 업로드 및 계산 요청 |
| `Common.h` | Windows·Winsock 공통 선언 |
| `ChatMsg.h`, `PrjClientFile.h` | 메시지 타입과 통신 헤더 |
| `ProtocolCore.h` | 패킷 길이 검사, 메시지 생성, ID·파일명 검증 및 수식 처리 |
| `NetUtil.h` | 연결과 전체 송수신, 제한시간·취소 처리 |
| `UiDispatch.h` | 작업 스레드의 UI 갱신 요청 전달 |
| `app.manifest` | UTF-8 코드 페이지 설정 |
| `tests/` | 핵심 로직 회귀 테스트와 TCP 통합 테스트 |
| `CHANGES.md` | 개선 사항 |
| `VALIDATION.md` | 수행한 검증과 추가 확인 항목 |

서버와 클라이언트는 각각의 Visual Studio 솔루션으로 빌드합니다. 기능별 소스는 `Feature01.cpp`, `Feature03.cpp` 등의 파일로 분리했습니다.

## 개발 환경 및 실행 방법

- 언어: C++14
- 운영체제: Windows 10 1903 이상 / Windows 11
- 개발 도구: Visual Studio 2022, MSVC v143, Windows SDK 10.0
- 주요 API: Winsock2, Win32 API
- 문자 처리: MultiByte 설정 및 UTF-8 코드 페이지

1. Visual Studio에 **C++를 사용한 데스크톱 개발** 구성 요소를 설치합니다.
2. 공통 헤더와 `app.manifest`를 두 프로젝트의 상위 폴더에 유지합니다.
3. `Term_Server/Term_Server.sln`과 `Term_Client/Term_Client.sln`을 각각 엽니다.
4. 두 프로젝트를 **Debug / x64**로 빌드합니다.
5. 서버를 먼저 실행하고 클라이언트에서 서버 IP를 입력해 연결합니다.
6. 사용자 ID를 등록한 뒤 채팅·파일 전송·계산 기능을 사용합니다.

같은 PC에서는 `127.0.0.1`을 사용합니다. 다른 PC에서 접속하려면 서버 PC의 IP와 TCP 9000·9001 방화벽 설정을 확인해야 합니다. 서버와 클라이언트는 동일한 개선본으로 함께 빌드해 사용합니다.


## 학습한 점

서버와 클라이언트가 동일한 메시지 규약을 사용해야 데이터를 올바르게 해석할 수 있다는 점을 배웠습니다. 타입과 길이 정보를 활용해 ID 등록, 채팅, 파일 전송 등 서로 다른 요청을 구분하고 처리했습니다.

특히 TCP의 송수신 호출과 메시지 경계가 일치하지 않는다는 특성을 바탕으로 수신 누적 버퍼와 송신 큐의 필요성을 이해했습니다. 버퍼 크기와 입력 길이를 검사하고 부분 송수신을 처리하며, 기능 구현에 더해 메시지 유실과 잘못된 입력에 대응하는 흐름을 학습했습니다.

GUI와 네트워크 작업을 연동하는 과정에서는 작업 스레드, UI 갱신 및 공유 자원 동기화를 다뤘습니다. 또한 원본 코드와 개선본을 구분하고 검증한 범위와 남은 확인 항목을 기록하는 방식으로 프로젝트를 정리했습니다.
